# ESP32 桌面工具 0.8.1 使用说明

设备保持 `480×320` 横向。原有触摸与显示驱动、时钟、亮度、SD 动态壁纸、AI 状态胶囊、确认卡片和物理确认 OTA 继续工作。

## 构建与运行

在公开仓库根目录创建 Python 虚拟环境、安装依赖，详见 [README](../README.md)。运行：

```sh
scripts/build_native_helper.sh
.venv/bin/pio run
.venv/bin/python mac_bridge/bridge.py run --no-cli
```

Bridge 默认使用本机 `mac_bridge/.runtime/`，该目录不入 Git。可用 `--library-root` 指定自己的壁纸库；不要同时启动两个占用 `8765/8766` 的 Bridge。原生助手在本机以 ad hoc 签名运行，没有分发签名或公证。网页管理入口为 `http://127.0.0.1:8766/`。

## 屏幕导航与壁纸

默认传感器构建的页面顺序：**首页 → Mac 系统 → 本地环境 → Mac 控制 → 信息卡 → 任务 → AI 用量**。在空白区域左右滑动切换；列表竖向滚动，音量滑条松手后才提交。主页按钮随时返回；Mac 系统页 15 秒闲置返回，其余工具页 60 秒，正在触摸或操作进行中会暂停计时。

所有页面先绘制当前本地动态壁纸，再叠加半透明面板。首页三块玻璃胶囊位于时钟和 AI 状态胶囊之间，显示任务数、Codex 周/五小时剩余、Claude 周/五小时预留。玻璃从当前壁纸取样、轻微柔化，随亮度切换文字颜色。点击任务或额度胶囊进入对应详情页；点击其他空白位置仍切换时钟显示。

动态壁纸源视频支持最大 **800 MB、10 分钟**，大小按 800 MiB（838,860,800 字节）计算。6/8/10/12 FPS 均可导入完整 10 分钟；设备需安装 0.8.1 或更新固件。Mac 自动转码为不超过 128 MiB 的 SD 播放包，最长 7200 帧。较长壁纸在传输后需要逐帧校验，期间继续显示旧壁纸，请等待“SD 卡本地播放”确认。

AI 用量页有 Codex 和 Claude Code 两个标签，展示真实窗口、已用/剩余、读取状态和重置倒计时。Claude 尚未接入时明确显示等待采集器，既不查询额度，也不制造 0%。

## Mac 控制

- **音量**：拖动本地预览，松手提交；20%、40%、60% 快捷值及静音。助手读取实际输出设备和结果。不支持软件音量的输出显示原因。
- **输出**：选择系统已经存在的音频输出。耳机蓝牙连接和当前音频输出分别显示；连接成功不会声称音频已经切换。
- **蓝牙**：已配对设备连接、断开、刷新。新配对和首次系统授权在 Mac 完成。
- **Mac Wi-Fi**：选择系统已保存网络，右侧确认切换。状态和“切换网络会断开 Bridge”提醒分开显示。需要密码、定位权限或交互认证时到 Mac 设置完成；不在设备上输入 Mac 网络密码。
- **隔空投送**：打开 Finder 的 AirDrop 窗口。文件卡打开携带指定文件的原生分享面板；接收者选择和真正发送由用户在 Mac 完成。

控制页顶部显示当前操作的进行中、成功、失败或未确认状态，下方提示也有独立玻璃背景。音频写入会等待实际读回，最长 3 秒；待机蓝牙耳机调节前另需约 1 秒准备。设备断开或输出变化时不宣布成功。蓝牙列表优先显示已连接设备并去掉重复引用，超时、设备未就绪和权限不足分别提示。

耳机待机时，页面显示“上次确认状态”；首次尚未确认则显示“音量暂未提供”，仍可使用快捷值或滑条调节。调节成功后更新已确认数值，恢复播放时重新读取当前状态。不同音频输出的支持情况以本机实际读回为准；本次公开整理没有执行音频或蓝牙操作。

操作结果为进行中、成功、失败或结果未确认。断线时保留操作编号，重连只查询旧结果并刷新当前状态，不自动重做连接或网络切换。设备设置管理 ESP32 自身的 Wi-Fi，与 Mac Wi-Fi 控制分开。

## 设备设置退出

Mac 控制等页面右上角的 **设备设置** 打开 ESP32 Setup Mode。点击下方 **退出设置** 回到主页，关闭临时配置 AP，保留 NVS 内的网络及 Bridge 设置，并重新连接已保存网络。没有保存网络时也允许退出并离线显示壁纸；不会因退出按钮擦除配置。

**BOOT** 长按 1.5–5 秒后松手仍可打开设置；5 秒清除配置行为保留。退出后如黄色连接点暂未变绿，表示设备还在重连 Bridge。

## 临时信息卡与二维码

在 Mac 网页“临时信息卡”主动创建：

- 文字：标题最多 48 UTF-8 字节，正文最多 512 字节。
- 链接：HTTP/HTTPS，最多 512 UTF-8 字节，禁止带用户名/密码的 URL。二维码由 ESP32 本地生成，手机扫码打开对应链接。它不是设备配对码或 Wi-Fi 密码。
- 文件：Mac 原生文件选择器登记；路径仅留在 Mac，小屏幕收到文件名和不透明引用。文件移动或删除后分享会报告不可用。

最多 5 张，默认 30 分钟到期，可选 5 分钟、30 分钟、2 小时。固定卡不自动到期；满 5 张固定卡时需要先清除一张。取消固定后保留 30 分钟。设备提供上张/下张、固定/取消固定、清除及文件分享按钮。

二维码有四模块白色静区，限制在右侧 172 像素高的区域，最长链接不会覆盖页眉或底部按钮。当前“二维码验收”卡的 `https://example.com/` 是公开测试地址。Mac 持久化卡片，设备在 RAM 缓存已同步内容；断开 Bridge 后还能看未到期缓存，冷启动后等待再次同步。

## 后台任务

用包装器主动运行命令，输出仍留在原终端：

```sh
scripts/task-run --title "测试" -- .venv/bin/python -m unittest discover -s mac_bridge/tests
scripts/task-run --title "构建" -- .venv/bin/pio run
```

标题最多 48 UTF-8 字节；默认连接本机 `8766`，可用 `--port` 覆盖。可用 `--source` 指定来源，以及 `--details-url` 登记 HTTP/HTTPS 详情入口。设备不会收到完整命令、命令参数或输出日志。

包装器启动、每 15 秒心跳、结束时上报，退出码 0 为成功，非 0 为失败。连续 45 秒没有更新显示“长时间未更新”，不会据此判定失败。可向包装器 PID 发送 `SIGUSR1` 显式声明等待输入，`SIGUSR2` 恢复运行；包装器在标准错误打印自己的 PID，不会自行猜测任意子进程是否正在等输入。

Mac 保存最多 32 条普通任务，设备同步最近 8 条，每页 4 条，优先淘汰已查看的终态任务。点击行显示摘要和最后更新时间，可标记已查看；未登记详情时不显示详情按钮。现有 Codex/Claude 状态作为“会话”，**本轮结束**只表示一轮结束，不代表整个项目、构建或测试成功。

## Codex 用量与提醒

Bridge 启动独立只读 Codex App Server 客户端，进行 `account/read`、`account/rateLimits/read` 并接收 `account/rateLimits/updated`，不创建模型任务。优先 `rateLimitsByLimitId`，兼容旧单桶响应；按实际 `window_minutes` 识别 300 分钟、10080 分钟或其他窗口，绝不按 primary/secondary 的位置猜测。

正在工作或用量页打开时约 60 秒刷新，闲置时约 5 分钟；进入用量页也会刷新。10 分钟无有效数据标记过期，停止产生新额度提醒。首次读取已经低额度时只提示最紧迫的一档，跨多档合并，多窗口同次触发也合并。

剩余 **25%、20%、15%、10%、5%、3%、1%、0%** 各档，同一窗口只提醒一次。去重在 Mac 持久化，重启不重复；确认账户更换或窗口更替后重新计算。到重置时间后需重新读取并确认恢复，之前已提示耗尽的窗口可补一次恢复通知。失败/字段缺失不算 0%，0% 只称“对应额度窗口耗尽”。提醒不抢占确认卡或 OTA。

官方接口：[Codex App Server](https://learn.chatgpt.com/docs/app-server)。进度 hooks 与用量读取是两条独立链路；App 内部读到额度不替代本项目独立采集器的验收。

## 协议及恢复

继续使用已配对 WebSocket；新增消息仅发给声明 `desktop_hub_v1` 的已配对设备：

| 消息 | 核心字段与用途 |
|---|---|
| `hub_snapshot` | section、revision、page/pages、total、observed_at、items；usage/tasks/cards/control 独立分区 |
| `hub_action` | operation_id、固定 action、已登记 target、必要 value |
| `hub_result` | 原 operation_id、state、reason |

控制包上限 2048 字节，同版本所有分页到齐才替换缓存；缺页、旧版本不会显示半份数据。新增可选能力 `desktop_hub_batch_v1`：新设备的 Mac 控制列表每页最多 4 项，正常 64 项只需 16 包；旧 `desktop_hub_v1` 设备保留每包 1 项。若一组 4 项超出包上限，整个控制分区回退为单项分页。控制分区接收窗口为 30 秒，其余分区为 10 秒。每设备串行同步，内容相同的分区不重复发送。控制列表最多 64 项，截断时明确提示到 Mac 设置操作。

动作仅接受固定枚举和已登记引用，不接受设备命令、路径或任意执行 URL。操作编号持久化去重；旧 `action` 的确认语义保持。恢复模糊结果时查询状态，不重放副作用。

升级时先构建对应环境，并显式发送自己的固件文件：

```sh
.venv/bin/python mac_bridge/bridge.py ota .pio/build/deskpet_sensors/firmware.bin --editor-port 8766
```

安装仍需实体屏幕长按 1.5 秒；收到新镜像身份及健康启动确认才算完成。参见 [OTA 与回滚](OTA.md) 和 [验证范围](VALIDATION.md)。私有历史恢复镜像没有随仓库公开。
