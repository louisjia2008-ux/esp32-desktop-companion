# 双传感器日常使用版 v0.9.2

本功能在现有 SC3248W535 工程内运行。默认仍为视频壁纸；从壁纸向左滑动依次进入 Mac 状态、本地环境、控制、信息卡、任务和用量。本地环境的主页按钮返回壁纸；页内「实时 / 曲线 / 雷达」标签切换本地视图，左右滑动仍按原全局页面顺序导航。

## 本地功能

- 环境页突出显示 CO₂，显示温湿度、有人状态和数据更新时间。启动、过期、恢复中、未连接均有明确提示；无新鲜数据时数字显示 `--`。
- 感应亮屏默认开启。只有新鲜、有状态及能量支持、距离大于零且不超过 100 cm 的运动或静止摘要目标保持唤醒。连续五分钟没有这种近距离目标后调暗；房间里更远的人不会阻止调暗，最近五分钟内触摸也保持唤醒。夜间继续使用原夜间亮度。雷达过期或状态未知时回退原触摸与定时亮度。
- CO₂ 提醒默认开启。有效读数连续至少五分钟达到 1500 ppm，仅在有效有人状态下显示本地 INFO 提示，十二秒后自动关闭；成功显示后至少三十分钟再提醒。低于 1300 ppm 结束该轮偏高状态。数据断档超过十五秒后需重新积累五分钟。其他事件、OTA、主动配网优先。
- 环境页下方两个开关分别控制上述功能，设置保存于独立 `sensors/cfg_v1` NVS 记录。关闭提醒不会隐藏偏高状态。旧 `display/disp_v1` 二进制布局没有变化。
- 这些功能不依赖 Mac Bridge 或互联网。已有配置的设备在网络不可用时仍可使用本地界面，即使 SD 没有就绪；主动配网界面仍优先。

## 雷达距离

实时页显示较近的有效报告距离；雷达页显示房间有人状态、有效运动/静止距离及能量、本次最远有效报告，以及是否符合 100 cm 亮屏范围。过期、无人残留、零能量或零距离不作为当前目标距离，显示 `--`。这仅改变本机亮屏判断，不发送雷达设置命令，仍保留远处目标用于观察。CO₂ 提醒继续使用房间有人状态，不受 1 米亮屏阈值限制。

LD2410C 不是逐人跟踪雷达。官方协议只有运动与静止摘要，没有人数、目标 ID 或逐人坐标；同时出现两种状态不能解释为两个人。这里的较近距离是两种有效摘要的最小值，并不保证等于实际最近一个人的距离。1 米是报告数值阈值，不能承诺严格的物理边界或测量精度。资料：[HLK 协议 V1.09 第 19–20 页](https://h.hlktech.com/download/HLK-LD2410C-24G/1/LD2410C%20%E4%B8%B2%E5%8F%A3%E9%80%9A%E4%BF%A1%E5%8D%8F%E8%AE%AE%20V1.09.pdf)。

## 每日空气曲线

曲线页显示选定本地日期的 00:00–24:00，支持 CO₂ / 温度 / 相对湿度切换，以及今天和此前六天的日期浏览。只聚合真实、唯一且新鲜的 SCD41 样本，每分钟保存一个均值，屏幕按五分钟均值显示。这里的分钟指实际收到样本的本地分钟，不保证满 60 秒或固定样本数；原始记录保留实际 sampleCount，图形汇总有少量整数舍入。未采集、过期、设备关闭、校时跳变或损坏记录对应的间隔不会被插值补齐；刚开始记录时一天中的大部分位置空白是正常现象。

记录使用独立 SD 目录 `/sensor-history/`、七个固定文件槽 `day0.ah1` 至 `day6.ah1`，包含版本与 CRC 校验。覆盖旧槽前识别本模块合法文件头，遇到未知文件不覆盖。不会删除壁纸文件、格式化 SD 或使用 NVS 保存高频测量。保存过的分钟在重启后渐进读回；当前尚未结束并落盘的分钟不能保证断电保留；同日原始记录上限为 2880 条，达到上限后停止追加并显示错误，防止反复校时无限增长。

历史时间沿用已有 Bridge 校时和时区偏移。一次校时之后，Bridge 断开仍按设备系统时钟继续记录；冷启动后尚未校时则明确等待时间，不把 uptime 或旧 NVS 日期伪造成今天。实时环境读数和距离亮屏不需要校时。七天曲线从安装这个版本后逐渐积累，不会凭空产生此前的测量。

历史读写由主循环统一管理，按小块执行；OTA、壁纸上传与验证期间暂停可选 SD I/O，采样任务仍运行。待写队列容量有限，超过容量会累计丢弃并断开曲线。FAT/SD 的单次同步操作仍可能耗时，小块预算不是硬实时保证；`AIR_HISTORY` 输出最大实际 I/O 用时、写入分钟、CRC/读写错误及队列丢弃累计。SD 缺失或不可用显示明确状态，不停止传感器、屏幕或网络。

## 传感器服务

`beginSensors()` 独立创建两路任务，`readSensorSnapshot(nowMs)` 返回一致的只读快照。UI 和策略不访问总线。

雷达沿用实测验证的 UART1 RX=44，256000 baud / 8N1，TX 禁用。超过两秒没有有效帧显示过期，继续监听并自动恢复。SCD41 独占 I²C1，SDA17/SCL18、100 kHz、地址 0x62，触摸保留 I²C0 的 GPIO4/8。SCD41 十五秒无新样本显示过期；连续三次通信错误或二十秒无有效样本进入恢复，每三十秒重试应答、型号及周期测量。计数不因恢复而清零。

采样任务不访问 USB，也不依赖日志初始化。正式版每十秒输出限速摘要及状态变化；USB 空间不足时丢弃整行并累计 `log_drops`。各传感器任务报告栈最小余量，主循环报告最小 Heap/PSRAM 和最大连续可用块。错误计数累计；SCD41 没有提供可可靠读取的内部复位计数，因此不能将无通信错误当成“传感器内部零复位”。

只执行地址探测、停止周期测量、读取识别与型号、启动周期测量、查询就绪和读取测量。没有校准、恢复出厂、配置持久化或雷达参数写入。

## Bridge 自动恢复

v0.9.1 保留现有 Bridge 地址、配对、Mac 协议与 Wi-Fi 策略，增加固定 WebSockets 2.6.1 的传输恢复适配层。断开后按退避间隔自动重试，最长间隔为三十秒；TCP 接通后，HTTP WebSocket 升级使用增量读取与五秒总时限。握手单行最多 512 字节、总头部最多 4096 字节。连续未连接九十秒后关闭并释放旧 TCP 对象，重新初始化 WebSocket 传输，保留配对及请求配置。恢复过程不调用 ESP32 重启、Wi-Fi 重置或 NVS 清除。

每次建立新会话都清除旧心跳失败状态。正式版连接日志使用有界 `RuntimeLog`，USB 未连接或输出拥堵不会阻止恢复调度。`WS_TRANSPORT` 十秒摘要区分 TCP 尝试、HTTP 升级超时、协议拒绝、传输重建、心跳初始化和连接/断开累计。

`max_attempt_ms` 包括一次同步 TCP 尝试及 HTTP 请求发送；`max_poll_ms` 包括传输 poll 和其中回调；`max_loop_ms` 是相邻两次主循环开始的最大间隔，包含调度及其他 I/O。原同步 TCP 连接仍有 1500ms 超时，已建立连接的帧 I/O 仍沿用原库，不能据此承诺所有网络操作完全无阻塞。公开快照的测试与真机验证范围见 [验证状态](VALIDATION.md)。

## 构建、测试与回退

默认 `pio run` 使用 `deskpet_sensors`。`jc3248w535` 保留无传感器版本；`ld2410c_rx_probe`、`scd41_probe`、`dual_sensor_probe` 保留详细诊断入口。不能同时启用正式服务和诊断探针。

Bridge CLI 的默认 OTA 文件同步为 `.pio/build/deskpet_sensors/firmware.bin`；回退无传感器版本时，先 `pio run -e jc3248w535`，再显式传入 `.pio/build/jc3248w535/firmware.bin`。自定义构建目录同样需要显式传入准确文件。

主机测试（仅离线验证，不代表真实读数）：

```sh
python3 scripts/run_sensor_tests.py --sanitize
python3 scripts/run_sensor_service_tests.py --sanitize
python3 scripts/run_sensor_ui_tests.py
python3 scripts/run_air_history_tests.py --sanitize
python3 scripts/run_runtime_log_tests.py
python3 scripts/run_network_recovery_tests.py --sanitize
python3 -m unittest discover -s tests/network -p 'test_reconnect_analysis.py'
```

真机采集：

```sh
python3 scripts/capture_sensor_runtime.py --port /dev/cu.usbmodemXXXX --output /private/tmp/sensor-runtime --seconds 1860
```

不要直接沿用默认 `pio upload` 写入未知槽位。烧录前重新读取分区表与 OTA 元数据，确认活动应用地址，备份精确的当前应用并校验哈希；仅写活动应用分区。保留 NVS、分区表和 SD。更改接线必须先断电。

长断开验收需要保持同一次设备运行，保留 Bridge 暂停/恢复的 UTC 日志，然后分析自动连接、配对挑战回答和 Mac 状态接收的有序证据。打开 USB 可能引发初始复位；不能在故障发生后重开串口或重启设备，再将重新启动后的连接当作自动恢复。采集与分析示例：

```sh
python3 scripts/analyze_bridge_reconnect.py --capture /private/tmp/sensor-runtime/runtime.jsonl \
  --pause /private/tmp/bridge-pause-1.jsonl --pause /private/tmp/bridge-pause-2.jsonl \
  --output /private/tmp/bridge-reconnect-analysis
```

3.3V 稳压器供电余量和独立电气测量依旧 **BLOCKED**。成功运行和软件测试不会将它们自动改为 PASS。该版本不承诺电气认证或测量精度。
